S

Situation

Ascender, CIQ’s open-source distribution of AWX, ships with an installer that deploys the application. A corporate deployment needs much more around it: a stable DNS name, a certificate from the corporate PKI, a host firewall, proof that everything works, and a way to back it up, upgrade it and renew its certificate later.

Without a written procedure, each installation is a one-off that only its author can repeat, review or support.

T

Task

Write the reference procedure for a dedicated Ubuntu Server 26.04 LTS host, so that an engineer with no prior exposure to Ascender or Kubernetes can reproduce the deployment by following the steps in order, and prove every step on a clean server.

A

Action

  1. Architecture firstHigh-level and low-level designs in draw.io: who uses the platform, its tiers, every Kubernetes object, host component, port and network path, plus each design decision and its rationale.
  2. TLS and DNS before the serverThe FQDN drives the ingress host rule, the CSRF trusted origins and the certificate SAN, so the DNS record and the corporate certificate are requested before anything is installed.
  3. Nine phases with expected resultsServer baseline, DNS and TLS, dependencies, k3s, host firewall, installer retrieval, configuration, execution and verification. Each step states the output that confirms it worked.
  4. Least exposureThe ufw host firewall follows the k3s guidance: SSH and the Kubernetes API only from the administration network, with the pod and service networks trusted.
  5. Pinned versions and reference filesA software bill of materials pins every component, and a copy of every file created on the server is kept in the repository, laid out by its absolute path.
  6. Day-2 operationsService management, logs, backup and restore, upgrade, certificate renewal, operating system patching, uninstall and troubleshooting.

What validation found

  • The installer asks APT for kubectl before it registers the Kubernetes repository, so a clean system fails early. Registering the repository first fixes it.
  • ufw does not filter the ports k3s ServiceLB publishes (they are forwarded through DNAT), so exposure of the web tier belongs at the perimeter firewall.
  • A failed project sync is “sticky”: re-running the installer re-evaluates the last update, so a fresh sync is needed first.
R

Result

  • ReproducibleA clean host reaches a working Ascender over HTTPS, with a corporate certificate, by following the guide in order.
  • ResilientA reboot and a full power-cycle test confirm that the platform comes back on its own before handover.
  • ReusablePublished under the MIT License for code and configuration, and CC BY 4.0 for the documentation and diagrams.
  • A foundationThe same platform runs my CIS Level 1 baseline and the self-healing lab.

What it means for a team

  • Repeatable installs: the next engineer follows a tested procedure instead of reverse-engineering the last one.
  • Secure by default: TLS from day one, a host firewall and documented network flows, ready for a security review.
  • Supportable: day-2 tasks and troubleshooting are written down before they are needed.
